# 简历点对照：每条 bullet 落在哪个文件的哪一行

这份文档只做一件事：**把简历里那四条 bullet 拆成"可被追问的具体断言"，每条断言对到一份代码位置，并给出该读到什么颗粒度。**
用法——面试前按 §1 走一遍，能对每一行说出"这段在证什么"；被追问细节时直接跳到对应行号。

> 行号对应 2026-10 这一次提交（`git log --oneline | head`）。代码改动后行号会漂，按文件 + 函数名定位。

---

## 0. 简历原文（被测的四句）

1. 参考 vLLM，从零实现 Qwen 系列推理引擎：PagedAttention、KV 显存池、前缀缓存 hash/radix、连续批处理与 chunked prefill、FlashAttention paged attention、Decode CUDA Graph、prefill torch.compile。
2. Qwen1.5-MoE 专家路由与 fused grouped GEMM；分布式并行（TP/PP/DP/EP）；n-gram 草稿投机（5.87×/1.75×）。
3. ZOS（Zero-Overhead Scheduling）：把下一步的 CPU 调度改到当前步前向已在 GPU 上跑之后，在途行的 token 由 GPU 侧 gather + remap 补齐；逐 token 对拍一致，cudaEvent 气泡探针显示每步步间空隙 0.29 ms → <0.01 ms。
4. 2×RTX 4090D 实测：Qwen3-0.6B 单卡 decode 449.7 tok/s、TTFT 5.1 ms（CUDA Graph + prefill compile）；TP=2 在 0.6B 上 −11%、8B 上 +63%（收益反转）；与官方 vLLM 0.30.0 的 8B 单卡 decode 差 2%。

## 2. 数字口径核对（**这一节比 §1 更要紧**）

简历一句话里混了两张表的两行，面试官对着表一核就会发现：

| 简历写法 | 文档原值 | 建议改法 |
|---|---|---|
| 单卡 decode **449.7** tok/s、TTFT **5.1 ms**（CUDA Graph + prefill compile） | `cg` 单开 = 449.7 / TTFT 25.86；`compile` 单开 = 50.3 / TTFT **5.07**；`cg+compile` = **446.8 / 5.36** | "单卡 CUDA Graph decode **449.7 tok/s**；叠加 prefill compile 后 TTFT **25.9 → 5.4 ms**、decode 446.8" |

已核对无误的三条：`TP=2 在 0.6B 上 −11%`（401.9 vs 449.7）、`8B 上 +63%`（58.1 → 94.6）、`与官方差 2.0%`（−2.0%）。
