# 架构总览

## 1. 分层

```
Engine（门面）             tokenizer / 请求生命周期 / 流式输出
  └─ EngineCore           唯一的推理循环：schedule → run → read_samples → finish
       ├─ Scheduler       准入、抢占、KV 记账、ZOS 在途账本（纯 CPU，不碰张量）
       ├─ Executor        UniprocExecutor（单进程）/ MultiprocExecutor（TP×PP）
       │    └─ Worker     建通信组、装模型、持有 KV 池与 ModelRunner
       │         └─ ModelRunner   组包 → 前向 → 采样 → D2H 分期
       └─ KVManager + BlockManager + PrefixIndex   分页 KV 的账本
```

控制面与计算面用两套数据结构对话：

- `ScheduledBatch`（CPU 侧）：本步要跑的 `Sequence` 对象列表。
- `SchedulerOutput`（跨进程，msgspec）：`prefills` / `decodes` 两段 `SeqSchedule`，字段固定顺序、只传必要标量（token id、块表、位置、采样参数）。
- 采样结果反向是 `(p_ids, d_ids)` 两个 Python list + 一个 `slot`。

跨进程只传"标量和小列表"，张量一律在 worker 侧由常驻 GPU 缓冲自己组装（`src/compute/batch.py`），避免每步序列化大张量。

## 2. 一次请求的生命周期

1. `Engine.add_request(prompt, SamplingParams)` → tokenize → `Sequence`（`src/data/sequence.py`）进 waiting 队列。
2. `Scheduler.schedule()`：decode 优先（保延迟），再用剩余 token 预算拉 prefill（chunked）；显存不够时 `preempt` 队尾序列。
3. `Executor.run(sched)`：把 `SchedulerOutput` 送给 worker（多卡时先 Gloo 广播，再各自执行），worker 组包 → 前向 → 采样，**只发射不等待**。
4. `Executor.read_samples(n_p, n_d, slot)`：唯一阻塞点，等采样结果的 D2H 事件。
5. `Scheduler.finish/update`：追加 token、判 EOS / max_tokens、还 KV 块（前缀缓存后端决定是否 publish）。

## 3. 关键数据结构

| 结构 | 位置 | 说明 |
|---|---|---|
| `Sequence` | `src/data/sequence.py` | token 列表、状态（WAITING/RUNNING/FINISHED）、`block_table`、`num_cached_tokens`、采样参数、ZOS 在途标记 |
| `KVManager` / `BlockManager` | `src/data/kv.py`、`src/data/block_manager.py` | 块分配（fresh / cached 复用）、`num_cached_tokens` 与块表同步、前缀命中 |
| `PrefixIndex` | `src/data/prefix/` | `none` / `hash`（xxhash 逐块链式）/ `radix`（基数树） |
| `SeqSchedule` | `src/data/batch.py` | 跨进程最小单元：`seq_id`、`block_table`、`num_cached_tokens`、`token_ids`、`need_sample`、采样参数、`remap`（ZOS） |
| `Batch` | `src/compute/batch.py` | 常驻 GPU 缓冲：`input_ids`、`positions`、`slot_mapping`、`cache_seqlens`、`cu_seqlens_*`、`block_tables`、采样参数 |

## 4. 计算面细节

**组包**（`src/compute/batch.py`）只写标量：位置 `pos = num_cached_tokens`、槽位 `slot = block_table[pos // 256] * 256 + pos % 256`、注意力长度 `csl = pos + 1`。块表按序列 id 做行缓存，命中就只补最后一格，避免整表重传。

**注意力**（`src/compute/layers/attention.py`）：prefill 走 `flash_attn_varlen_func`（cu_seqlens 打包，支持带前缀缓存），decode 走 `flash_attn_with_kvcache`（直接吃分页 KV + `block_table`）。没有 flash-attn 时退回 `_flash_attn_fallback.py`（纯 torch SDPA）。

**采样**（`src/compute/sampler.py`）：整批贪心时直接 `argmax(hidden)` 跳过词表投影；否则算 logits 后按 `temperatures/top_ps/top_ks/min_ps` 向量化处理，整批布尔量（`all_greedy` / `use_top_k` / ...）都在 CPU 侧算好，避免 GPU→CPU 同步。

**CUDA Graph**（`src/compute/cuda_graph.py`）：decode 按 batch 档位（`make_bs_list`）捕获；`_pad_bs` 把当前 bs 对齐到最近档位，padding 行的 `slot_mapping=-1`、`cache_seqlens=0`、`block_tables=-1`，保证不写脏数据。PP 时中间张量的收发放在图外。

**torch.compile**：prefill 首 chunk 编译（`compile_dynamic` 控制符号形状），TP 时用 `max-autotune-no-cudagraphs` 避免图冲突。

## 5. 并行

| 维度 | 切法 | 通信 |
|---|---|---|
| TP | 切 head / 切权重（`VocabParallelEmbedding`、`RowParallelLinear`、`ColumnParallelLinear`） | 每层 all-reduce |
| PP | 切层（`pp_layer_counts` 支持不均分） | p2p 收发 `IntermediateTensors` |
| EP | 按专家切（`enable_ep`），token 留本地 | 出口 all-reduce（未做 DeepEP 式 all-to-all） |
| DP | 起多个独立 Engine 副本 | 无（各自独立进程组） |

采样固定在最后一个 PP stage 的 tp0（`_sampler_rank`），结果再回传 driver。PP 下 driver 侧的阻塞等待是已知的吞吐上限之一（`src/control/executor.py` 文件头注释）。

## 6. 与 vLLM 的差异（有意为之的简化）

- 只支持 Qwen3 dense / Qwen3-MoE，没有通用模型注册与权重映射层。
- 调度器是单线程、单队列模型，没有 priority / fair-share。
- 没有 openai 兼容 server 与 metrics 导出。
- 前缀缓存只做块级（256 token）匹配，没有 mid-block 命中。
