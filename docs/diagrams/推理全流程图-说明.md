## 1. 四卡分工一页纸（TP = 2 × PP = 2，4 卡 2 进程）

| 卡 | 段（PP stage） | 层 | Q 头 | KV 头 | 词表 | 采样 |
|---|---|---|---|---|---|---|
| 卡 0 | 段 0 | 0–13 | 0–7 | 0–3 | 前半 | — |
| 卡 1 | 段 0 | 0–13 | 8–15 | 4–7 | 后半 | — |
| 卡 2 | 段 1（末段） | 14–27 | 0–7 | 0–3 | — | ★ 只有它采样 |
| 卡 3 | 段 1 | 14–27 | 8–15 | 4–7 | — | 不算采样，算完等下一轮 |

- PP 切层公式：`num_hidden_layers × stage / pp_size`（28 层、pp=2 ⇒ 0–13 / 14–27）。
- 每段一个进程（`InferEngine` 持本段的 tp 张卡）；TP 组是节点内集合通信，PP 用 TCP rendezvous 建组。
- 末段的 `lm_head` 在卡 2/卡 3 上**完整复制**（不是词表并行），所以两张卡的 logits 逐位相同；采样只在 `pp_rank == last` 且 `tp_rank == 0` 的那张卡上发生。

## 2. 两套账本（数据在 GPU、账本在 CPU）

- **ⓒ CPU**：`BlockManager` / `KVManager` / 前缀索引。`block_table` 是纯 Python 整数列表，含义只有一个：**逻辑位置 → 物理块号**。
- **ⓖ GPU**：KV 池 `pool[2, 28, blocks × 256, 8, 128]`（`kvcache_block_size = 256`）。
- 字节账：每 token 每层 `2 × 8头 × 128维 × 2 B = 4 KiB` ⇒ 每 token 全 28 层 **112 KiB** ⇒ 4096 token = **448 MiB**；每块每层 `2×8×256×128×2 B = 1 MiB` ⇒ 每块 28 层 **28 MiB**。
- 前缀索引只收**满块**（半截块的内容下一步还会变）。

## 3. 通信账（本机 2 × RTX 4090D，无 NVLink、P2P = NS）

- 每层 2 次 allreduce（① `o_proj` 按输入维切 ⇒ 部分和；② 专家 / `down_proj` 合并）；一次前向 = `2 × 28 + 1 = 57` 次（+1 是首段词表并行的求和）。
- 实测：allreduce 8 KB = **76.7 µs**，all-reduce busbw 7.09 GB/s。
- 0.6B 每个 decode 步 ≈ 224 KB ⇒ 通信 ≈ **2.15 ms** ⇒ **TP = 2 反而更慢**（37.9 vs 单卡 49.5 tok/s）。
- ⚠ 本项目**没有**「全局方差归一化」那一次通信 —— 那是另一个项目（MiniMax Lightning 层）的设计，别串场。

## 4. 并行的三个轴

- **TP**：切输出维 ⇒ 行并行那半条要归约（部分和）；切求和维 ⇒ 完整切片、零通信（判据一句话：「求和轴被切 ⇒ 必须归约；输出维被切 ⇒ 零通信」）。
- **PP**：sync lockstep 切层，不是 1F1B；只正向送 `h` 与 `residual` 两项，不经 CPU。
- **DP**：`dp_size` 份完整引擎副本，**副本之间零通信**（实测 dp2 = 1.73×（cg）/ 1.88×（eager））。DP 的分叉在 client 层（`make_client`），TP/PP 的分叉在 Executor 层。
- **EP**：在现有 TP rank 上切专家轴；每卡算全部 token、只算自己那部分专家，合并仍是一次 allreduce。

## 5. 图内 / 图外（piecewise CUDA Graph）

- 图内：decode body（读写固定地址的静态 buffer）；图外：PP 的 recv / send。
- 按 batch size 分档捕获（1, 2, 4, …，上限 `min(max_num_seqs, 256)`；batch 不在档位内就回退 eager）。
- prefill 走 `torch.compile` 图，前提是**这一批没有任何前缀命中**（命中后 Q 长度 ≠ K 长度，编译图把形状写死了）。
- 编译热身真的会往 KV 写东西，所以热身完必须 `kv_cache.zero_()`，否则残留被后续请求当成「前文」。

## 6. 前缀缓存与抢占

- 三个后端：`noop` / `hash` / `radix`；**换后端必须重建整条链**（页池语义变了，旧调度器还攥着旧引用）。
- 命中的前缀不重算：prefill 只算 `num_cached_tokens` 之后的部分。
- 抢占牺牲队尾：v6 只做 **recompute**（重读 prompt 的 prefill，compute-bound 且可与其他请求并行），不换出到 CPU。

## 7. 为什么这些内容不画在图上

早先的版本试过把上面这些做成图里的「说明框」，挂在交接① 上。结果是：**框会参与 dagre 排版**，既占画布又把这些框塞进簇的缝里，把主干的走向带偏。所以现在统一成：

- 图上：只有流程节点 + 真正属于流程的通信节点（allreduce / PP 发送）。
- 图外（本文件）：账本、字节账、带宽、图/编译、前缀缓存、抢占。

口径提醒：所有数字都标了出处与机器前提（2 × 4090D、无 NVLink、P2P = NS），换机器要重算。
